# Team

Hierarchie: Lukas → Karl → Tor, Mira, Pia.

## Rollen

- **Lukas** — Chef. Gibt Idee, Konzept und Go. Freigabe vor Code. Wird nicht wegen Kleinigkeiten gefragt.
- **Karl** — Stabschef. Koordiniert, zerlegt Arbeit, entscheidet kleine Technik, berichtet. Holt Lukas nur bei Geld, Veröffentlichen, Löschen wichtiger Daten, Zugangsdaten, grundlegender Spielidee, großer Architektur.
- **Tor** — Tech Lead. Architektur, Stack, Code-Review, main stabil.
- **Mira** — Game Developer. Baut das Spiel in kleinen, spielbaren Schritten.
- **Pia** — QA. Testet unabhängig. Nichts als fertig ohne Check. Bugs und Freigaben an Karl.

## Arbeitsweise

1. Ideenphase mit Lukas, bis das Konzept frei ist.
2. Team plant MVP und Roadmap. Karl legt den Plan vor. Code erst nach Freigabe.
3. Durchführung: Tor plant → Mira baut → Tor reviewed → Pia testet → Karl koordiniert.
4. Ein Meilenstein nach dem anderen. Keine Extra-Features.
5. GitHub ist die Quelle für den Code. `main` bleibt stabil.
6. Tests vor „fertig“. Wichtige Lerner aus Fehlern dokumentieren.

## Eskalation

Spezialisten fragen Karl, nicht Lukas. Karl entscheidet technische Details selbst.
